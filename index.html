selected work

The one worth looking at closely.

Full build — product + automation

Hayes Ride

A ride-booking web app where the interesting part isn't the site — it's what happens when a customer calls instead of clicking. The front end is Next.js with MongoDB behind it; a Gemini-powered agent handles the conversation and hands it off to an n8n workflow that checks availability and books the ride, live, with no dispatcher in the loop.

The workflow listens on a webhook, resolves the request against the Hayes booking APIs, and writes the result straight back into the same database the web app reads from — so a phone booking and a web booking end up looking identical on the back end.

process

How an automation actually gets built.

01

Map the real conversation

Before any code, I write out what a customer actually says and what has to happen in response — the workflow gets designed around that, not the other way around.

02

Design the workflow in n8n

Each step in the conversation becomes a node: check availability, validate details, write to the database, trigger a confirmation.

03

Connect the real systems

The workflow talks to the actual product APIs and database — not a mock — so what it books is what shows up in the app.

04

Give it a voice or a chat window

A Gemini-backed agent sits in front of the workflow, handling the call or chat and passing structured requests down the pipeline.

05

Ship it and watch it run

Deployed, then watched against real calls for a while — edge cases in a live conversation show up fast, and the workflow gets tightened from there.
